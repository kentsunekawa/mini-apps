# mini-apps

バックエンドとインフラを、小さなアプリを1本ずつ作りながら身につけるためのリポジトリ。
各アプリは一つの「問い」を確かめるために作り、答えが出たら閉じる。

## 1 本の流れ

1. **問いを決める**：確かめたいことを 1〜2 個、作る前に文章で書く
2. **先に自分で設計する**：テーブル、API の形、処理の流れを雑でいいので書く。ここは AI に聞かない
3. **手で書く**：AI は質問相手として使う
4. **比べる・壊す**：同じものを AI にも書かせて比べる。別の書き方を試す、わざと壊す、実行計画を見る
5. **記録して閉じる**：各アプリの README に残す。AWS に載せた回は Terraform で壊す

## ルール

- 1 本は 1〜2 週間で閉じる。完成度より、問いに答えが出たら終わり
- フロントは作らない。API を curl や HTTP ファイルで叩くだけ
- Phase 0 は ORM なし、Phase 1 から Prisma
- 各アプリは完全に独立させる。package.json も依存も別々。共通部品は作らない

## AI の使い方

- Phase 0 は全部手書き
- Phase 1 以降は、問いに関わる所は手書き、それ以外は AI に任せていい
- 問いが道具そのもの（Terraform、S3 など）の回は、その道具の部分を手書き
- 毎回、同じものを AI にも書かせて自分のと比べる

## 構成

```
mini-apps/
  README.md         このファイル（一覧と回し方）
  TEMPLATE.md       各アプリの記録のひな形
  log.md            週の記録と月の振り返り
  compose.yaml      ローカルの PostgreSQL（全アプリ共通）
  001-vocab-api/
    README.md       その回の記録（TEMPLATE.md をコピー）
    package.json
    src/
    db/
```

## ローカルの DB

```sh
docker compose up -d
```

PostgreSQL が `localhost:5432` で立ち上がる。アプリごとに別のデータベースを作って使う。

```sh
docker compose exec db createdb -U dev vocab_api
```

## スタック

- 言語：TypeScript（運用スクリプトは Python）
- ランタイム・フレームワーク：Node.js、Hono
- DB：PostgreSQL（Phase 1 から Prisma）
- インフラ：AWS、Terraform、Docker、GitHub Actions
